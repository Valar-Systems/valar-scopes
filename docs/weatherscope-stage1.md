# Weatherscope Stage 1: one stored MRMS frame on the round screen

**Predictions, committed 2026-10-20 before any decoder or env code exists.** Results go in [Results](#results) against these tables, never edited after the fact. A result off its prediction: stop and report, no tuning and retrying. A result the tables do not name: the instrument is unreliable at this scale; stop and decide.

The screens and their rulings are in `docs/weatherscope-screens.md` (PR #425). This stage draws **one stored frame**: no network, no live data.

## What gets built

**A. `include/WxCrop.h`, the WXC1 decoder.** A pure C++ header, shared with the Blipscope weather spike's Part B. Agreed with `blipscope-5c` through Daniel on 2026-10-20. It goes to `main` as a small PR of its own; no shipping build includes it, so it can land without touching v18.
- **Spec:** "Wire format v1" in `docs/wx-spike-2026-10.md`, with `encodeAt` and `decodeCrop` in `tools/wx/crop.ts` (both on `spike/wx-overlay`).
- **Interface:** header parse, a run callback `(row, col0, len, code)`, and a helper that fills a buffer the caller provides. **It allocates nothing.**
- **Refuses the whole crop, never a partial grid, on:**
  - a wrong magic or version;
  - a coarsen value other than 1, 2, 4 or 8;
  - 0 rows or 0 columns;
  - input over 32,768 bytes;
  - a body that overruns, or whose runs don't add up to rows × cols;
  - a LEB128 length that is truncated or longer than 5 bytes.

**B. The `weatherscope-s3-128` env.** A bench harness on the `animtest-s3-128` pattern: `build_src_filter = -<*> +<weatherscope_main.cpp> +<weather/>`, LovyanGFX only, no Wi-Fi, no config page, no OTA. The full edition comes in Stage 2: `FEATURE_WEATHER`, the config page, `FW_OTA_PREFIX` and the data path.
- **The frame:** it embeds `test/fixtures/wx/kdfw-60mi.wxc` with `board_build.embed_files`, so no generated `.inc` can go stale ([CLAUDE.md](../CLAUDE.md) on SCons and `#include`d data).
- **On boot:**
  1. decode into a code grid in PSRAM;
  2. work out each screen row's and each screen column's cell index, in double precision;
  3. render 240 × 240 into a PSRAM sprite with the provisional palette;
  4. push it once;
  5. print timing and memory lines, then dump the per-pixel code buffer for comparison with the host reference.
- **Landing:** its shared files (`platformio.ini`, a slug-less `skus.yml` row) land only after the v18 prerelease is cut and verified (`blipscope-5c`, 2026-10-20).

**Projection** (Stage 1 is north-up). It is the radar's `AircraftManager::ProjectAt`:
- linear in degrees around home, at 111.0 km per degree;
- longitude scaled by cos(home latitude), with a floor of 0.01;
- **without the radar's 2.0° clamp.** That clamp protects an OpenSky box; 60 mi is far below it, and Weatherscope has no such box.
- **Home** is the crop's centre, taken from its header.
- **Each pixel** is sampled at its centre, and its cell index is `floor(v + 0.5)`.
- **A pixel off the disc** is code 255. **A pixel whose cell is outside the crop** is code 14 (no coverage, never dry).

The host reference that implements exactly this is `test/fixtures/wx/render_ref.py`.

**Board.** The Weatherscope board is USB serial `907069326E64`, which `board-port.py` still registers as `blipscope`. It is not flashed until Daniel confirms the v18 grade doesn't need it, and `blipscope-5c` reads its uptime first (for the #245 follow-up). Its port is resolved from that serial, never from a COM number.

**Two references agree on every fixture.** `check_fixtures.py` decodes everything with the spike's independent Python decoder (`decode()` in `tools/wx/a3_check.py`).
- **Valid crops:** 4/4 codes sha256 agree with crop.ts.
- **Bad crops:** 3/3 are refused by both.
- **Corpus:** 50/50 crops round-trip to the encoder's own cells, and 50/50 twins are refused.
- **Its control** (one code changed in the KDFW crop) reads MISMATCH, as it must.

**Location rule:** each crop is centred on a public airport at least 150 km from every coordinate in the repo, checked with the spike's `forbidden.py`. Its control passed (a scanned point reads TOO CLOSE, a far point reads clear).
- KDFW, KPHX, KMSP and the corpus airports come from the spike's vetted list (50/50 clear). The generator reads only that list.
- PHNL was checked separately and is clear.
- KLAX, from the spike's unvetted candidate list, is **within 150 km** of a repo coordinate and was rejected (10 others on that list are too).

`MANIFEST.json` holds no coordinates. Each crop's header carries its north-west cell centre, and `make_fixtures.ts` carries PHNL's.

Its own objects (animation code, coastline and border data, its main) account for about 82 KB of text + data and about 10 KB of data + bss. That leaves about 442 KB of flash and 20 KB of RAM for the framework, LovyanGFX and the variant.

| B9. The dumped 57,600-byte per-pixel code buffer | **sha256 `344383b4cfae04eec5a7a844cfb5f1b9aaa4ce8fa15f30d1b956d4e86ac05225`**, identical to `render_ref.py` | see below |

**What B9 looks like** (`docs/images/weatherscope-stage1-kdfw-reference.png`, provisional palette):
- **Layout:** the north half is dry. The storms are south-east, with smaller cells to the south-west.
- **Echo share:** by quadrant, SE 75 %, SW 21 %, NE 1 %, NW 0 %. Overall, 24.4 % of the 45,244 disc pixels show echo.
- **Strongest:** code 10, on one pixel.
- **No grey:** no pixel is no-coverage, because 0 cells fall outside the crop. The crop's cell rounding absorbs the 111.0 vs 111.32 km-per-degree difference at 60 mi.

**Sabotage S-B1:** latitude sign flipped (north and south mirrored). Predicted: buffer sha256 `91bbb69d6ef6…`, with only **52.1 %** of disc pixels and **0.6 %** of echo pixels equal to the reference. B9 **fails**.

**How it is measured:**
- **Serial lines:** `WX,…` for timing and memory, and `WXFB,<base64>` for the buffer, read with `scripts/bench-trace.ps1` (a single open, never reattached).
- **Comparison:** a host script compares the buffer with `render_ref.py`.
- **Flash and RAM:** from the build output.

**Pre-registered outcomes off the tables:**
- **B9 not identical:**
  - If at most 0.1 % of disc pixels differ **and** every differing pixel's cell is one row or column from the reference's, that's double rounding or a libm last-bit difference: stop and report.
  - Anything else is a FAIL.
- **B1-B8 outside their bands:** stop and report.
